## Objective

Set up distributed tracing with Jaeger. You will:

- Enable tracing in Istio
- See one request as a timeline across frontend and backend
- Understand how trace IDs move between services
- Fix the most common reason traces do not appear

## Why tracing

A request in a microservice system can cross many services. Metrics tell you that something is slow. A trace tells you **which hop** is slow.

Envoy sidecars can record spans and send them to Jaeger. One condition applies: the request must carry trace headers, for example `x-b3-traceid` and `x-b3-spanid`.

In the current setup:

- The frontend runs plain `curl`. It sends no trace headers.
- The backend is a static echo server. It adds no trace headers.

Envoy sees plain HTTP with no trace context, so nothing appears in Jaeger. This part fixes that.

## Step 1: A frontend that sends trace headers

Replace the frontend with a loop that sets B3 headers on every request. This simulates an application with tracing support.

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
spec:
  replicas: 1
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
      - name: frontend
        image: curlimages/curl
        command: ["sh", "-c"]
        args:
          - |
            while true; do
              TRACE_ID=$(od -vAn -N8 -tx1 /dev/urandom | tr -d ' \n')
              PARENT_SPAN=$(od -vAn -N8 -tx1 /dev/urandom | tr -d ' \n')
              curl -s http://backend \
                -H "x-b3-traceid: $TRACE_ID" \
                -H "x-b3-spanid: $PARENT_SPAN" \
                -H "x-b3-sampled: 1"
              sleep 5
            done
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: frontend
spec:
  selector:
    app: frontend
  ports:
  - port: 80
    targetPort: 80
EOF

```

## Step 2: Keep the backend

The backend (`hashicorp/http-echo`) needs no change. Its Envoy records a span as soon as it sees the trace headers.

## Step 3: Enable tracing in Istio

The demo profile does not turn on tracing by default. Create `istio-jaeger-tracing.yaml`:

```yaml title="istio-jaeger-tracing.yaml"
apiVersion: install.istio.io/v1alpha1
kind: IstioOperator
spec:
  profile: demo
  meshConfig:
    enableTracing: true
    defaultConfig:
      tracing:
        sampling: 100
        zipkin:
          address: jaeger-collector.istio-system.svc.cluster.local:9411
    accessLogFile: /dev/stdout
    accessLogEncoding: TEXT
    accessLogFormat: '[%START_TIME%] "%REQ(:METHOD)% %REQ(X-ENVOY-ORIGINAL-PATH?:PATH)% %PROTOCOL%" %RESPONSE_CODE% traceID=%REQ(X-B3-TRACEID)% spanID=%REQ(X-B3-SPANID)% service=%DOWNSTREAM_LOCAL_ADDRESS%'
```

Apply it:

```bash
istioctl install -f istio-jaeger-tracing.yaml -y
```

This configuration:

- Turns tracing on for the mesh
- Samples 100% of requests. Use a lower value in production.
- Sends spans to the Jaeger collector on port 9411
- Adds the trace ID and span ID to each access log line

## Step 4: Restart the applications

The sidecars load the new configuration on restart:

## Step 7: Traces in Jaeger

Forward the Jaeger UI port:

```bash
kubectl port-forward svc/jaeger-collector -n istio-system 16686:16686
```

Open http://localhost:16686 and search for these services:

```txt
frontend.default
backend.default
```

![Jaeger trace timeline for frontend to backend](/images/2025/istio_part6_tracing.webp)

Each trace shows the hops, the latency of each hop, and the mTLS connection between them.

## How it works

<Flow steps={['frontend Envoy: new trace', 'mTLS', 'backend Envoy: child span', 'Jaeger collector :9411']} label="Both Envoys send spans to the Jaeger collector, which joins them into one trace" />

1. The frontend Envoy sees the `x-b3-*` headers and starts a span.
2. The call goes to the backend Envoy over mTLS. The headers travel with it.
3. The backend Envoy creates a child span with the same trace ID.
4. Both Envoys send their spans to the Jaeger collector on port 9411.
5. Jaeger joins the spans into one trace.

## Key terms

| Term | Meaning |
| ---- | ------- |
| Trace ID | One ID for one request across all services |
| Span ID | One segment of a trace, usually one hop |
| Jaeger collector | Receives spans from Envoy |
| Sampling | Share of requests that get traced |
